# Project notes for the agent

- AGENTS.md lists the idiosyncrasies of the data and the logic the first build turned up (box-score coverage, the gap rule, positions, debuts, what each sequence means). Read it before changing the ledger builder or the engine, and add to it when a gate or a reader teaches us a new one.

- What it is: a query engine for WNBA career-point comparisons ("Delle Donne has 2,042 points through her first 100 games"). A reader sets a five-slot sentence (who · did what · how much · over which games · against whom) and the board ranks every career, or every player-season, by its value at that window. It is the NFL Comparator (`~/Projects/nfl-comparator`) over a basketball ledger; the planning spec is in the CFB repo, `cfb-streak-king/specs/nfl-career-point.spec.md`, and the NFL repo's CLAUDE.md and AGENTS.md are the reference for anything not said here. Keep the two engines in step when one learns something.
- Data: wehoop (sportsdataverse) release files, CC BY 4.0, two pipelines. The spine is the WNBA Stats player game logs (`player_game_logs_<season>.csv`, 1997 on, every game); the ESPN box scores (`player_box_<season>.csv`, 2003 on) fill any game the logs lack (the running season's tail when the Stats pipeline is behind, as 2026's was) and supply the starter flag, joined by player and date through wehoop's crosswalk (`wnba_player_crosswalk_<season>.csv`), the ESPN bios (`player_core_<season>.csv`) the birth date and a position, the WNBA Stats rosters (`rosters_<season>.csv`, 1997 on) a position for nearly everyone ESPN lacks, and `data/ref/positions.json` the researched positions for the rest, each row with its receipts (the method is the receipts-research skill: `data/research/positions/` holds the worklist, the research files with their saved pages, and the triage; `npm run receipts` string-checks every quote against the saved pages, `npm run merge:positions` builds the ruling file from the research files, `npm run coverage` prints what's still missing). `npm run fetch` downloads them into `data/raw/` (gitignored; the running season's files refetch after a day). `npm run ledger` (`scripts/build-ledger.mjs`) writes one file, `src/data/players.json` (committed; the site builds without the raw files). A row is a game the player appeared in, with the result, the starter flag (or none), the team's game number that season (`tgn`) and the stat line; `COLS` in the builder is the layout and `src/lib/ledger.ts` decodes it. Players are keyed by the WNBA Stats id. The whole ledger ships with the page (about 8MB, 2MB gzipped); split it by position if that ever hurts.
- Rulings the words rest on (also in `Notes.jsx`): a game is an appearance (the logs have no row for a player who didn't play), a start is ESPN's starter flag and is null for a game with no box score (every game before `startsSince`, 2003, and the 109 ESPN misses after), so a career that began before 2003, or has a flagless game inside its window, sits out the starts fields and the board counts it (`board.gapped`); a win is the result of a game in the sequence; the All-Star game and the Commissioner's Cup final aren't in the logs, the Cup's regular-season games are; a position is ESPN's, else the WNBA roster's, else researched (`posSrc` says which), and every player has one; the engine still treats a null as sitting out the position fields, in case a new player arrives before any source names her; the regular season is the default and `scope=all` adds the playoffs; ranks are competition ranks with ties.
- The known-answer gate is `src/lib/query.test.ts`: Cooper's 621 points in 1997, Catchings's 594 in 2002, Wilson's 1,021 in 2024, Clark's 337 assists and two triple-doubles in 2024, Ionescu's 128 threes in 2023, Charles's 398 rebounds in 2010, Bueckers's 44-point game in 2025, plus the starts rule. `scripts/gate.mjs` prints the same numbers and a few career boards. Add a gate for every factoid the site is asked to reproduce, with the publisher's definition noted where it differs.
- Rulings the engine adds: a clean-game test (`max: 0`, "no turnovers", "no fouls") holds only in a game the player had ten minutes or more (`played()`, `PLAYED_MIN` in `query.ts`, inside `holds()` so the board, the panel's ticks and the worker agree; AGENTS.md has the numbers).
- Code layout: `src/lib` is TypeScript (`npm run typecheck` checks it and the worker, see below), components JSX. `query.ts` is the engine (`evaluate` → ranked rows, the ones still inside the window, and the gapped count; `curve`, `crossings`, `toMatch` are the peer primitives), `stats.ts` the stat catalog (noun, thresholds; every stat is every position's, and `dd`/`td` are per-game 0/1s), `words.ts` every sentence the page says, `compare.ts` the comparison the panel shows (`peersOf`/`peerOf`/`compare`/`crossingWords`/`matchWords`), `share.ts` the words a link carries (`SITE`, `shareTitle`, `shareDescription`, `claimWords`, `shareText`, `cardHeading`, `cardRows`, `cardComparison`, `isShared`; the same two modules under the same names as NFL's), `url.ts` the query in the URL (one param a slot, defaults omitted, `t` the open player, `vs` her peer, which rides only with `t`), `analytics.ts` the `track` helper. `pos` is a filter on the field (`ALL`, `G`, `F`, `C`), not a ledger.
- The page, top to bottom (the sports-site skill's page anatomy): the dateline (`drewhoover.com · 1997–2026 · updated`, one text node) with the icon bar (the player finder, Ko-fi, share); the h1; the sentence; the one footnote; the board with the open row's panel **inline under its row** (`Board.jsx` `brow-wrap`; the page extends so the open row is always rendered, a `?t=` link lands on the row after hydration, and a position change that drops the open player out of the field closes her); What to read next; "Using a comparison from here" with the citing ask and Ko-fi; Method (`id="method"`); the footer; comments. `document.title` is set client-side whenever the query, the open row or the peer changes, with the same words the worker writes, and goes back to the page's own title at the bare address. The share button is Streak King's `useShare` (`src/hooks/useShare.ts`: the native sheet where there is one, else copy "text url" and flash copied; the text is the open row's claim, else the sentence; `track('share', { words, player, vs })`).
- Ko-fi is `KOFI_URL` in `Notes.jsx` (`https://ko-fi.com/drewhooverdotcom`), three placements, each `track('kofi', { from })`: the coffee cup in the icon bar (`icons board`), the notes line (`notes`), the footer (`footer`). No button, no badge, no orange.
- The player finder (`PlayerFinder.jsx`, the dateline's magnifier) filters `public/players/index.json`, which `scripts/build-records.mjs` writes with the records (id, name, position, span, games, `n` her rows, `top` her best score; `npm run build` runs it first, `npm run records` alone; gitignored). A pick goes to her page when she has one (`n` > 0), else opens her row on the board and lands on it (her latest season on a player-season board).
- Player pages and the records mine: `src/lib/records.ts` is NBA Comparator's miner (the method is NFL's `specs/player-pages.spec.md`) read over this ledger through a flat view, with the board's fields (a starts sequence stops at the first game without a box score; a season is in at N once the team has played N, and in the mine's season field once she started half the team's games or averaged 15 minutes). `scripts/build-records.mjs` writes `public/players/<id>.json` for every player who leads something (373 on the 2026-10-22 ledger); `PlayerPage.jsx` renders `/player/<id>/` (families by stat, the face of each, the rest behind "more", every row a link to its board, `?tune=1` the tuner); `main.jsx` routes it without loading the ledger bundle; the prerender writes each page with its file embedded, Person JSON-LD, the sitemap entry, and `dist/player/<id>/og.png` (`scripts/lib/og-player.mjs` over `scripts/lib/og.mjs`). `records.test.ts` is the gate (Cooper's 2,187 through 100 games, Wilson's 1,021 in 2024, Clark's 337 assists, Bird out of the starts fields, the file round trip, the page nesting in the mine). The face of a family is its best score, which is usually a count or streak row ("16 games with 30+ points in her first 100 games" over "2,187 points through her first 100 games"); that is the spec's open question, and the knobs are in `RECORDS`.
- Look: College Football Streak King's (dark stadium palette, Graduate for numbers, Source Serif for words, Plex Mono labels, dashed-underline pickers; `Picker.jsx` and `Icons.jsx` are copied from it). Every select is `Picker.jsx`, a Radix dropdown; no native `<select>`. Rust is for data, never chrome.
- Vite + React static site for GitHub Pages under drewhoover.com, from the dataviz-project-template: `package.json` "name" is the URL slug and must equal the repo name; `site.config.js` the title and OG copy; `npm run build` is `vite build` plus `scripts/prerender.mjs`, so `main.jsx` hydrates and nothing reads `window` during render (URL state is applied in an effect). Shareable state goes in the URL with `replaceState`. Analytics is `window.dhAnalytics?.track`, optional-chained (`src/lib/analytics.ts`). The repo is `DrewHoo/wnba-comparator`, live at `https://drewhoover.com/wnba-comparator/`; `.github/workflows/deploy.yml` deploys on every push to `main` (the Pages build, then the worker job).
- Social previews: drewhoover.com's DNS is on Cloudflare (origin stays GitHub Pages), and the share worker (`workers/share/`, name `wnba-comparator-share`) sits on `drewhoover.com/wnba-comparator/*`. For a URL whose query says more than the root (a slot off its default, or `t=` open) it rewrites `<head>` with the words from `src/lib/share.ts` (pure, tested; a crawler's request also loads the ledger, so its title and description name the leader, or the open player read against her peer, `vs=` or the leader: her claim, the peer's, where the curves met, the to-match line; a browser's gets the pure sentence and the page sets its own title on hydration) and points `og:image` at `/wnba-comparator/share/og.png?<the same params>`, which it draws with workers-og (`card.ts`; the fonts ride beside it): the board's top rows, or, with a player open, the comparison card (her and her peer side by side, the panel's two curves, where they met and the to-match line; `cardComparison` in share.ts, NFL's card), from `dist/share/players.json`, the ledger the prerender copies out (raw-GitHub fallback). The `worker` job in `deploy.yml` deploys it after every push to main (not the daily refresh) with the `CLOUDFLARE_API_TOKEN` repo secret; by hand, `npm run worker:deploy` (wrangler is OAuth-logged-in on the dev machine). The card's heading is sized to the 720px safe column (`SAFE` in `card.ts`) by character count (`headingSize` in `card.ts`) so it never wraps. The card's edge cache is keyed by `CARD_VERSION` in `index.ts`: bump it with any change to what a card draws. To see a card before deploying: `npm run build`, `npx vite preview --port 4173`, `npm run worker:dev` (which points `ORIGIN` at the preview and silences the analytics report), then open `http://localhost:8787/wnba-comparator/share/og.png?n=50` (and `?t=<id>&vs=<id>`, and a crawler's head with `curl -A Slackbot`). The worker holds the ledger in memory for the UTC day, so restart it after a new build. `wrangler` is pinned in devDependencies at the version `deploy.yml` runs; `workers/share/tsconfig.json` typechecks the worker with the Workers runtime types (the DOM lib and workers-types can't share a program: their `CacheStorage` collide) (`npm run typecheck` runs it, `npm run typecheck:worker` alone). Anything the worker can't word passes through untouched, so the site never depends on it.
- Search: every page the prerender writes is in `dist/sitemap.xml`, which the index site's `sitemap-index.xml` (the one registered in Search Console and Bing) lists through the `sitemapUrl` on this project's card there. The named definition pages are `src/lib/landing.ts`: a curated table of queries, each at its own path (`/fastest-to-1000-points/`), prerendered as the board on that query with an h1 worded as the question, a title in the searcher's words, a lead sentence naming the leader, and ItemList JSON-LD of the top rows (generated from the same `evaluate` the page renders). The path is the query's canonical address: `toAddress` (landing.ts) writes it whenever the board is on that query (`t` rides along), `parseLocation` reads it, `main.jsx` seeds the app from it so the hydrate matches, and the share worker passes a landing through untouched unless a player is open on it. The root is the default query and must not be a landing (`landing.test`). `Landings.jsx` lists every one under the board as real links. The prerender also writes `dist/llms.txt` (one line per question with its leader) and the deploy's `indexnow` job pings IndexNow (`scripts/indexnow.mjs`; the key is the `public/<key>.txt` file, public by design): the root and the landing pages on a push, the whole sitemap on the daily refresh. Add a landing when a query is something people type; keep slugs as the question's words.
- Dev server: `npm run dev` (the preview config runs it on 5176). Tests: `npm test` (Vitest, next to the code).
- Images: `npm run gen:favicon` copies drewhoover.com's own favicon set from the index repo; `npm run gen:og` draws `public/og.png` and `public/card.png` from the real default board, the title in Georgia Bold from the Mac's own copy (so run it on a Mac). Both are committed; re-run `gen:og` after a redesign or when a fresher board is worth committing, and open the PNGs. The project card on the index site is `src/content/projects/wnba-comparator.md` there, with `card.png` as its cover; update it in the same pass as a redesign.
- Years are never typed: `site.config.js` imports `FIRST_SEASON` from `scripts/lib/window.mjs` for the description (and so the OG, Twitter and JSON-LD copy), and the page reads `firstSeason`, `startsSince` and `currentSeason` from the ledger (the era picker, the starts hint, the dateline, Method).
- `deploy.yml` builds on push from the committed ledger, and on the daily 12:00 UTC schedule (or a manual run) refetches wehoop and rebuilds the ledger first, so last night's games reach the site without a commit.
- Team pages: `src/lib/groups.ts` (CFB Comparator's group pages, by franchise) ranks every guard, forward and center with 10 or more regular-season games for a franchise, keyed by its current team id with its earlier ids folded in (`FRANCHISES`: the Aces carry the Starzz and the Silver Stars, the Wings the Shock, the Sun the Miracle, and the ledger's PHO and PHX are one Mercury), the six folded teams under their own ids. `GroupPage.jsx` renders `/team/<id>/<guards|forwards|centers>/` (the curves of the first three metrics for the top eight, then the table; a name links to her page where she has one) and `/team/` the index; the prerender embeds each page's data (`#group-data`), so neither loads the ledger, and draws a card per page (`scripts/lib/og-group.mjs`). 63 pages over 21 franchises on the 2026-10-22 ledger. `groups.test.ts` checks that every team id in the ledger belongs to one franchise. The metrics are `GROUP_METRICS` (points first for all three; then assists, threes, steals for guards; rebounds, assists, steals for forwards; rebounds, blocks, assists for centers). The board's Questions list links the index.
